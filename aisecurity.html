The Semantic Video Search Perception Gap
Designing transparency for crop-frame constraints.

Problem:
Perception Gap & Business Impact

Semantic video search promises to let operators search through videos using everyday natural language. Users expect the same behaviour as how they interact with LLMs: you can type anything, and you'll be shown the relevant results.

However, a big problem happens because looking at the whole video perfectly is way too expensive for companies to build and store. To save money, most systems use a more cost-effective method that only looks at a tiny cropped square around an object. This creates a "hit or miss" problem. Simple searches work perfectly, but complex searches fail completely if the subjects fall outside that isolated crop boundary.

Let's see how this works in AI Video Security. When users start interacting with the search, they see a mismatch in how they understand the feature and how it actually works.

This mismatch can show as:

  • Manual Scroll Backlog: Operators don't find what they were looking for, meaning they still have to scroll through long search results manually.
  • The Rewording Loop: Some queries work, some don't, so they start rewording the same search a few times, unsure if the problem is their phrasing or the tool.

Technical Limitations:
How Crop-Frame Search Works

Primarily, what the AI model does is search for indexed identifiers (such as a person or a vehicle). Once these identifiers are found, the model looks for those specific elements and creates a cropped frame based on the search query. This cropped frame also becomes the thumbnail in the search results.

For example, if a user searches for "person wearing a red cap", the model's first step is to locate a person and create a cropped frame around them. It then checks for the cap within that cropped area. If the cap fits inside the cropped frame, the result "person wearing red cap" is displayed. In this scenario, there is a high chance of a successful search result because a cap worn by a person stays in direct contact with their body, naturally falling within the crop boundary.

By contrast, consider a search query like "person watching television". If the television is in close proximity to the person, it will fall within the cropped frame and appear in the results. However, if the television is positioned farther away, it will be excluded from the crop and will not appear in the search results.

When an object isn't confirmed inside the crop, the system doesn't always return nothing — it can still surface a smaller set of possible matches, clearly marked as unconfirmed, rather than hiding them.

Solution:
Designing Semantic Search Journey

01

Before Typing: Search Examples

What is happening:
A rotating placeholder inside the empty search input cycles through valid phrasing patterns (e.g., "person wearing red cap") before the user interacts.

How it helps:
Acts as passive, zero-friction onboarding. It nudges operators on how they can form their search query.

02

During Search: Showing What's Being Searched

What is happening:
As the system processes a query, an inline status message translates the user's sentence into plain system logic. If the query names something attached to a person, like "person with a red cap," it mirrors that directly: "Searching for person with red cap...". If the query names something merely nearby, like "person watching television," it says so plainly: "Searching for person near television..."

How it helps:
Shows the operator how the AI is actually thinking about their query, in real time: whether it's treating the object as something confirmed on the person, or something it's only checking for close by. This sets the right expectation for the result before it even loads.

03

When There's No Person or Vehicle: Filling the Gap

What is happening:
When a search has no person or vehicle at all (e.g., "grapes"), the system discloses that it added the anchor on its own: "Searching for grapes near person or vehicle..."

How it helps:
Makes clear the system never searches on its own. It always needs a person or vehicle to attach to, even when the user didn't ask for one.
